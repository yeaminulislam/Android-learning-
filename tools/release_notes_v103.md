## 🩺 v1.0.2-তে যা হয়েছিল, এখন যা ঠিক হলো (বাগ ৩)

v1.0.2 ইনস্টল ঠিকই হচ্ছিল, কিন্তু খুললেই স্প্ল্যাশ-স্ক্রিনে লাল বার্তা —
**“ডেটাবেস প্রস্তুত করা যায়নি”** + `SQLiteException: near "(": syntax error`।

কারণ: `Repository.java`-তে `SELECT_BASE` ধ্রুবক শেষ হত `… s.row_seq, s.extinct`
দিয়ে — **শেষের কমাটি ছিল না**। পরের অংশ `SELECT_EXTRA` যোগ হলে SQL দাঁড়াত:

```sql
SELECT s.id, …, s.row_seq, s.extinct IFNULL(tc.bn_name, …) AS class_bn, …
--                                ^ কমা নেই → syntax error
```

প্রথম পৃষ্ঠাই এই কুয়েরি চালায়, তাই ডেটাবেস-প্রস্তুতির ধাপেই থেমে যেত।
(খারাপ খবর: এটি আপনার ফোনে গিয়ে ধরা পড়েছিল। ভালো খবর: অ্যাপের ত্রুটি-পর্দা
ঠিকমতো কাজ করেছে — চুপচাপ বন্ধ না হয়ে পূর্ণ SQL-সহ কারণ দেখিয়েছে, আর আপনার
স্ক্রিনশট থেকেই বাগটি হুবহু চেনা গেছে।)

**ঠিক:** কমা বসানো হয়েছে। পাশাপাশি নতুন `tools/test_sql.py` — এটি
`Repository.java` থেকে SQL ধ্রুবকগুলো **সরাসরি পড়ে** নেয় (আলাদা কপি নয়), আর অ্যাপের
**৫৪টি কুয়েরির প্রতিটি** আসল ৪৩১ MB ডেটাবেসে কম্পাইল করে দেখে। সম্পূর্ণ ও ডেমো —
দুই ডেটাবেসেই **৫৪/৫৪ পাস**। এই ধরনের ভুল এখন আর ডিভাইসে পৌঁছাবে না।

## 🩺 আগের সংস্করণগুলোর যে বাগগুলোও ঠিক আছে

### বাগ ২ — “অ্যাপ ইনস্টল হয়নি” (v1.0.1)

প্যাকেজার `resources.arsc`-কে অসংকুচিত রাখত ঠিকই, কিন্তু **৪-বাইট অ্যালাইন** করতে
পারত না (প্যাডিং Python-এর `zipfile` মুছে ফেলত):

```
v1.0.1 : resources.arsc  STORED  off=3351   3351 % 4 = 3   ❌
v1.0.3 : resources.arsc  STORED  off=3348   3348 % 4 = 0   ✅
```

Android 11 (API 30) থেকে ইনস্টলারের শর্ত — অসংকুচিত `resources.arsc` অবশ্যই
৪-বাইট অ্যালাইন হতে হবে, না হলে “প্যাকেজ পার্স করা যায়নি / অ্যাপ ইনস্টল হয়নি”।

ঠিক: ZIP-এর প্রতিটি বাইট এখন নিজে লেখা হয় (লোকাল হেডার, প্যাডিং, সেন্ট্রাল
ডিরেক্টরি, EOCD), আর লেখার পরে ফাইলটি আবার পড়ে যাচাই হয়। `classes.dex`-ও এখন
অসংকুচিত ও অ্যালাইনড — ART সরাসরি mmap করতে পারে, ইনস্টল দ্রুত হয়।

### বাগ ১ — খুলেই বন্ধ হয়ে যেত (v1.0)

বিল্ডে **১১০টি রিসোর্স-id-ই ভুল** ছিল: `gen_r.py` কাল্পনিক id (0x7f010001…) বসাত,
আর `resources.arsc`-এ আসল id ছিল টাইপ অনুযায়ী (0x7f01… color, 0x7f04… string,
0x7f05… style)। ফলে প্রথম রিসোর্স-লুকআপেই `Resources$NotFoundException` —
স্ক্রিন এক ঝলক দেখেই অ্যাপ বন্ধ।

ঠিক: আগে `aapt2 link --output-text-symbols R.txt`, তারপর নতুন `tools/r_from_txt.py`
সেই আসল id দিয়ে R.java বানায়, তারপর কম্পাইল।

### প্রতিটি বিল্ডে স্বয়ংক্রিয় যাচাই

- `tools/verify_apk.py` — R.java ↔ R.txt ↔ resources.arsc মিল · সব STORED এন্ট্রির
  ৪-বাইট অ্যালাইনমেন্ট · ডেটা-ডেস্ক্রিপ্টর ফ্ল্যাগ · PKDB1 ডেটাবেস অ্যাসেটের আকার ও
  SHA-256 · dex-এর adler32/SHA-1 · ম্যানিফেস্টের ৯টি ক্লাস dex-এ আছে কি না ·
  v1+v2 স্বাক্ষর-ব্লক। **কোনোটি ফেল করলে বিল্ড ব্যর্থ হয়**
- `tools/test_sql.py` — অ্যাপের ৫৪টি SQL কুয়েরি আসল ডেটাবেসে কম্পাইল হয় কি না (বাগ ৩ ধরত)

### সমস্যা হলে দেখার ব্যবস্থা (এবার প্রমাণিত হয়েছে — আপনার স্ক্রিনশটেই!)

- **ক্র্যাশ-রক্ষী** — কোনো ত্রুটি হলে অ্যাপ চুপচাপ বন্ধ না হয়ে স্ক্রিনে **পূর্ণ
  স্ট্যাক-ট্রেস** দেখায় (কপি/শেয়ার বোতামসহ) এবং `filesDir/crash/*.txt`-এ লেখে
- **রোগ-নির্ণয় পর্দা** (সেটিংস → রোগ-নির্ণয়) — ডিভাইসের তথ্য + ৮টি সরাসরি পরীক্ষা
  (ডেটাবেস খোলা, গণনা, জনপ্রিয় পৃষ্ঠা, বিভাগ-পেজিনেশন, বাংলা ও ইংরেজি অনুসন্ধান,
  ছবি আঁকা, পছন্দ-ডেটাবেস), প্রতিটিতে সময় মাপা
- ফোনে জায়গা কম বা অ্যাসেট পাওয়া না গেলে স্পষ্ট বাংলা বার্তা
- মেমোরি কমানো: ডেটাবেস mmap ১২৮ → ৬৪ মেগাবাইট, পাতা-ক্যাশ ১২ → ৮ মেগাবাইট
