## ডাউনলোড ও ইনস্টল

দুটি সংস্করণ — একই অ্যাপ, শুধু ভেতরের ডেটাবেসের আকার আলাদা:

| ফাইল | আকার | প্রজাতি | ডেটাবেস |
|---|---:|---:|---|
| `dist/install-test.apk` | ১৭ KB | — | নেই (শুধু ইনস্টল পরীক্ষা) |
| `dist/prakriti-kosh-demo.apk` | ৭.৩ MB | ২০,০০০ | ৩৪ MB → ৭ MB |
| `dist/prakriti-kosh.apk` | ৭৬ MB | ২,৫০,০০০ | ৪৩১ MB → ৭৬ MB |

মোবাইল নেটে প্রথমে ছোটটি নামিয়ে দেখে নেওয়া বুদ্ধিমানের কাজ; ভালো লাগলে সম্পূর্ণটি
নামান। দুটো একই কীতে স্বাক্ষরিত, তাই ছোটটির ওপর সম্পূর্ণটি সরাসরি আপডেট হিসেবে
বসবে (ডেটা মুছে যাবে, কারণ ডেটাবেস বদলায়)।

ছোটটি আলাদা করে বানাতে:

```bash
bash tools/build_diag.sh      # install-test.apk (১৭ KB, ডিভাইস-পরীক্ষা)
python3 tools/build_dataset.py --total 20000 --demo 400 \
        --out data/dist-demo --web /tmp/demoweb

cp data/dist-demo/prakriti_kosh.db.z /tmp/assets-demo/db/
ASSETS_DIR=/tmp/assets-demo APK_NAME=prakriti-kosh-demo.apk bash tools/build_apk.sh
```

ফোনে ব্রাউজার থেকে APK নামিয়ে ট্যাপ করলেই ইনস্টল হবে; "অজানা অ্যাপ ইনস্টল করা"
অনুমতি চাইলে Allow দিন (debug-কীতে স্বাক্ষরিত, প্লে-স্টোরের বাইরের অ্যাপ)।
কম্পিউটার থেকে:

```bash
adb install -r dist/prakriti-kosh.apk
```

প্রথমবার খোলার সময় ৭৫.৯ মেগাবাইট সংরক্ষণাগার খুলে ৪৩১ মেগাবাইট ডেটাবেস তৈরি হয়

### সূচক (index)

```sql
-- ট্যাক্সোনমি ও পেজিনেশন
idx_species_group   (group_id, row_seq)
idx_species_class   (group_id, class_id, row_seq)
idx_species_order   (group_id, class_id, order_id, row_seq)
idx_species_family  (group_id, class_id, order_id, family_id, row_seq)
idx_species_popular (popularity DESC, id)
idx_species_iucn / venom / danger / extinct / demo

-- অনুসন্ধান (নামের সূচক + FTS5 পূর্ণ-পাঠ)
idx_species_bn        (bn_name)
idx_species_en_lower  (lower(en_name))
idx_species_sci_lower (lower(sci_name))
species_fts           -- FTS5, নাম + বাসস্থান + খাদ্য + তথ্য
```

পরিমাপ করা অনুসন্ধান সময় (২.৫ লক্ষ সারিতে): `Panthera` ০.২ মি.সে.,
`মাছরাঙা` ৫.৫ মি.সে., `সুন্দরবন` ৮ মি.সে., `বাঘ` ৬৪ মি.সে.,
`নীল তিমি` (FTS5 ফ্রেজ) ২০৫ মি.সে.।

## কর্মক্ষমতার নকশা

- **কীসেট পেজিনেশন** — `WHERE row_seq > ? ORDER BY row_seq LIMIT 25`;
  OFFSET নয়, তাই শেষ পৃষ্ঠায়ও গতি একই। এক পৃষ্ঠায় ২৪টি সারি।
- **জনপ্রিয়তা-ক্রমে পেজিনেশন** — `popularity < ? OR (popularity = ? AND id > ?)`
  (যৌথ কীসেট), `idx_species_popular` ব্যবহার করে।
- **শুধু দরকারি ডেটা** — তালিকায় প্রথমে শুধু `id, row_seq` পড়া হয়, তারপর
  একটিমাত্র জয়েন-কুয়েরিতে ২৪টি পূর্ণ সারি (`byIds`, UNION ALL দিয়ে ক্রম অক্ষুণ্ণ)।
- **সব ডেটাবেস-কাজ ব্যাকগ্রাউন্ড থ্রেডে** — ৩-থ্রেড এক্সিকিউটর + প্রধান থ্রেডের
  Handler; UI থ্রেডে কখনো কুয়েরি চলে না।
- **ছবি প্রোগ্রামে আঁকা** — কোনো ছবি-ফাইল নেই। প্রতিটি প্রজাতির id/শ্রেণি/বাসস্থান
  থেকে বীজ (seed) বানিয়ে ক্যানভাসে পটভূমি, সিলুয়েট ও নকশা আঁকা হয়
  (৪টি পরিবেশ-রূপ)। ফলে ২.৫ লক্ষ প্রজাতির ছবিতে ০ বাইট খরচ।
- **বিটম্যাপ ক্যাশ** — RGB_565 + LruCache (হিপ-এর ১/৮, সর্বোচ্চ ২৪ মেগাবাইট);
  `onTrimMemory`-তে খালি হয়।
- **SQLite টিউনিং** — `cache_size=-12000`, `mmap_size=128MB`, `temp_store=MEMORY`,
  প্রজাতির ডেটাবেস পঠন-মাত্র (read-only), `ANALYZE` করা।

## বিল্ড (Gradle/Android Studio ছাড়া)

স্যান্ডবক্সে কোনো Android SDK ছিল না, তাই পুরো পাইপলাইন হাতে সাজানো:

```bash
bash tools/build_apk.sh          # dist/prakriti-kosh.apk
python3 tools/build_dataset.py --total 250000   # ডেটাবেস + .db.z নতুন করে
```

ধাপগুলো (`tools/build_apk.sh`):

| ধাপ | টুল | কাজ |
|---|---|---|
| ১ | `tools/gen_r.py` | রিসোর্স থেকে `R.java` |
| ২ | Eclipse ECJ 3.45 | `.java` → `.class` (`-bootclasspath android.jar`, source/target 1.8) |
| ৩ | D8 8.2 (R8) | `.class` → `classes.dex` |
| ৪ | aapt2 | রিসোর্স কম্পাইল |
| ৫ | aapt2 link | ম্যানিফেস্ট + রিসোর্স → base APK (binary manifest + `resources.arsc`) |
| ৬ | `tools/pack_apk.py` | `classes.dex` + `assets/` যোগ, ৪-বাইট অ্যালাইনমেন্ট |
| ৭ | apksigner | v1 + v2 স্বাক্ষর |

দরকারি টুলগুলো npm/PyPI থেকে আসে:
`@drxiaozhi/minapk` (d8.jar, ecj, apksigner.jar, android.jar, debug.keystore),
`aaptjs3` (Linux aapt2), `jdk4py` (JRE 25 — java চালাতে)।

ডেটাবেসের সংরক্ষণাগার বিন্যাস **PKDB1** (৪৮ বাইট হেডার):

```
0..4    magic    "PKDB1"
5..6    version  uint16 LE = 1
7       flags    uint8 = 0 (gzip)
8..15   raw_len  uint64 LE
16..47  sha256   মূল ফাইলের হ্যাশ
48..    gzip স্ট্রিম
```

অ্যাপ হ্যাশ ও আকার যাচাই করে, তারপর ডেটাবেস `filesDir`-এ লেখে এবং
`.ready` মার্কার ফাইল রাখে।

### বাগ ৪ ও ৫ — সার্চ ও সেটিংস পর্দা সম্পূর্ণ ফাঁকা (v1.0.3-তেও, ডিভাইসে ধরা পড়ে)

`SearchActivity` ও `SettingsActivity` — এই দুটি স্ক্রিন **কখনো `requireDb()` ডাকত
না**। সব স্ক্রিনের ভিত্তি `BaseActivity`-তে ডেটাবেস প্রস্তুত হলে `onDbReady()` চলে,
আর সেটি ডাকা হয় `requireDb()` থেকে — অন্য চারটি স্ক্রিন (প্রধান, তালিকা, বিস্তারিত,
শ্রেণিবিন্যাস) সেটি ডাকত, এই দুটি ডাকত না। ফলে `build()` কখনোই চলত না: স্ক্রিনে
শুধু টুলবার, তার নিচে সম্পূর্ণ ফাঁকা — খোঁজার বাক্স, বাটন, সেটিংসের সারি কিছুই নয়।

**ঠিক (v1.0.4):** দুটি স্ক্রিনেই `onCreate()`-এ `requireDb()` + একবারই-বানানোর
গার্ড (`built` ফ্ল্যাগ)। পাশাপাশি প্রধান পর্দায় প্রতিবার ফেরায় 🔎/⚙ আইকন
ডুপ্লিকেট হওয়ার বাগও ঠিক (`clearToolbarActions()`)।

  সোয়াইপ-গ্যালারির **প্রথম পৃষ্ঠা** আসল ছবি (“আসল ছবি — সংগৃহীত”), বাকি পৃষ্ঠায়
  আগের আঁকা রূপগুলো
- উৎস-স্বীকৃতি: `data/photos/manifest.json`-এ প্রতিটি ছবির উৎস-সাইট
- টুল: `tools/photos_pack.py` — jpg/png/gif → WebP, তারপর ডেটাবেসের id মিলিয়ে
  `assets/photos/<id>.webp`; নাম না মেললে হিসাব দেখায় (ডেমো ও সম্পূর্ণ — দুই
  ডেটাবেসেই আলাদা করে বসে)
- জেনারেট-করা (কাল্পনিক) নামগুলোর আসল ছবি থাকতে পারে না — তাদের জন্য

### বাগ ৩ — “ডেটাবেস প্রস্তুত করা যায়নি” (v1.0.2, ডিভাইসে ধরা পড়ে)

v1.0.2 ইনস্টল ঠিকই হয়েছিল, কিন্তু খুললেই স্প্ল্যাশ-স্ক্রিনে লাল বার্তা:
`SQLiteException: near "(": syntax error`। কারণ — `db/Repository.java`-তে
`SELECT_BASE` ধ্রুবকটি শেষ হত `… s.row_seq, s.extinct` দিয়ে (**কমা ছাড়া**), আর তার
পরের `SELECT_EXTRA` শুরু হত ` IFNULL(tc.bn_name, …)` দিয়ে। দুটি জোড়া লাগলে SQL দাঁড়াত:

```sql
SELECT s.id, …, s.row_seq, s.extinct IFNULL(tc.bn_name, …) AS class_bn, …
--                                ^ এখানে কমা ছিল না → syntax error
```

প্রথম পৃষ্ঠাই এই কুয়েরি চালায়, তাই ডেটাবেস-প্রস্তুতির ধাপে থেমে যেত।

**ঠিক করা হয়েছে:** কমা বসানো হয়েছে (v1.0.3)। পাশাপাশি নতুন `tools/test_sql.py` —
এটি `Repository.java` থেকে `SELECT_BASE`/`SELECT_EXTRA`/`JOIN_TAXONOMY` **সরাসরি পড়ে**
(আলাদা কপি নয়, তাই Java বদলালে পরীক্ষাও বদলায়), বাকি ৫০+ কুয়েরি-টেমপ্লেট আয়নায় রাখে,
এবং সবগুলো আসল ৪৩১ MB ডেটাবেসে `EXPLAIN` + চালিয়ে দেখে। এখন ফলাফল:
**৫৪/৫৪ কুয়েরি পাস** (পূর্ণ ও ডেমো — দুই ডেটাবেসেই)।

    python3 tools/test_sql.py                 # ডিফল্ট: data/dist/prakriti_kosh.db
    python3 tools/test_sql.py data/dist-demo/prakriti_kosh.db

এই বাগটি আগে ধরা পড়েনি কারণ Python-পাশের পরীক্ষায় SQL হাতে টাইপ করে নেওয়া হয়েছিল —
Java-র আসল স্ট্রিং পরীক্ষাই হত না। এখন একক উৎস Java নিজেই।

### বাগ ২ — “অ্যাপ ইনস্টল হয়নি” (v1.0.1)

`tools/pack_apk.py` আগে Python-এর `zipfile` দিয়ে ZIP আবার লিখত আর `extra` ফিল্ডে
প্যাডিং বসাত। কিন্তু `zipfile.writestr()` সেই প্যাডিং রাখে না — ফলে `resources.arsc`
STORED হয়েও ৪-বাইট সীমায় বসত না:

```
v1.0.1 : resources.arsc   STORED  off=3351   3351 % 4 = 3   ❌
v1.0.2 : resources.arsc   STORED  off=3348   3348 % 4 = 0   ✅
```

Android 11 (API 30) থেকে ইনস্টলারের শর্ত — `resources.arsc` অবশ্যই **অসংকুচিত ও
৪-বাইট অ্যালাইন**। না হলে “প্যাকেজ পার্স করা যায়নি / অ্যাপ ইনস্টল হয়নি”।
(v1.0-তে এটি কাকতালীয়ভাবে ৪-এর ঘরে পড়েছিল — তাই সেটি ইনস্টল হয়েছিল,
তবে ভেতরের বাগ ১-এর কারণে খুলেই বন্ধ হত।)

**ঠিক করা হয়েছে:** ZIP-এর প্রতিটি বাইট এখন নিজে লেখা হয় — লোকাল হেডার, প্যাডিং,
সেন্ট্রাল ডিরেক্টরি, EOCD। তাই প্রতিটি STORED এন্ট্রি নিশ্চিতভাবে ৪-এর ঘরে বসে, আর
লেখার পরে ফাইলটি আবার পড়ে যাচাইও হয়। পাশাপাশি `classes.dex` এখন STORED ও
অ্যালাইনড — ART সরাসরি mmap করতে পারে, ইনস্টল দ্রুত হয়।

### বাগ ১ — খুলেই বন্ধ হয়ে যেত (v1.0)

বিল্ড স্ক্রিপ্ট আগে `tools/gen_r.py` দিয়ে নিজে কাল্পনিক রিসোর্স-id (0x7f010001,
0x7f010002 …) বসাত, কিন্তু APK-র `resources.arsc` তৈরি হত `aapt2 link` দিয়ে —
যেখানে id বসে টাইপ অনুযায়ী (0x7f01… color, 0x7f02… drawable, 0x7f04… string,
0x7f05… style)। **১১০টি id-র একটিও মিলত না**, ফলে অ্যাপের প্রথম রিসোর্স-লুকআপেই
`Resources$NotFoundException` ছুটত।

| রিসোর্স | ভুল id | আসল id |
|---|---|---|
| `R.color.green_dark` | `0x7f01000c` | `0x7f010007` |
| `R.string.app_name` | `0x7f01002f` | `0x7f040005` |
| `R.style.Theme_Prakriti` | `0x7f01006d` | `0x7f050005` |

**ঠিক করা হয়েছে:** বিল্ডের ধাপ বদলে আগে `aapt2 link --output-text-symbols R.txt`
চলে, তারপর `tools/r_from_txt.py` সেই **আসল** id দিয়ে R.java বানায়, তারপর
ECJ → D8 → প্যাকেজ → স্বাক্ষর।

### এখন প্রতিটি বিল্ডে যা যাচাই হয় (`tools/verify_apk.py` + `tools/test_sql.py`)

- R.java ↔ R.txt ↔ `resources.arsc` — প্রতিটি id মিলছে কি না (বাগ ১ ধরত)
- ZIP-এর প্রতিটি STORED এন্ট্রি ৪-বাইট অ্যালাইন কি না (বাগ ২ ধরত)
- `resources.arsc` ও `classes.dex` অসংকুচিত কি না
- PKDB1 ডেটাবেস অ্যাসেট: হেডার, gzip ম্যাজিক, আকার, SHA-256, SQLite হেডার
- `classes.dex`: ম্যাজিক, adler32, SHA-1, ক্লাস-সংখ্যা
- ম্যানিফেস্টের ৯টি ক্লাস dex-এ আছে কি না
- v1 + v2 স্বাক্ষর-ব্লক
- **SQL (আলাদা স্ক্রিপ্ট):** অ্যাপের ৫৪টি কুয়েরি আসল ডেটাবেসে কম্পাইল হয় কি না
  (`tools/test_sql.py` — বাগ ৩ ধরত)

### ইনস্টল না হলে যা করবেন

1. **পুরোনো সংস্করণ আনইনস্টল করুন** — সেটিংস → অ্যাপ → প্রকৃতি কোষ → Uninstall।
   পুরোনো সংস্করণের ৪৩১ মেগাবাইট ডেটাবেসও মুছে যাবে, জায়গা ফিরবে।
2. **মুক্ত জায়গা দেখুন** — সম্পূর্ণ সংস্করণে প্রায় **৫১০ মেগাবাইট** লাগে
   (৭৬ MB APK + ৪৩১ MB ডেটাবেস); ছোট সংস্করণে প্রায় **৪১ মেগাবাইট**।
3. **SHA-256 মিলিয়ে নিন** — ফাইল অসম্পূর্ণ নামলে ইনস্টল হবে না।
4. **`install-test.apk` (১৭ কিলোবাইট) ইনস্টল করুন** — এটি একই পাইপলাইন ও একই
   কীতে স্বাক্ষরিত একটি ফাঁকা অ্যাপ (`com.prakriti.diag`)। এটি ইনস্টল ও চালু হলে
   বুঝবেন ডিভাইসে আমাদের APK ইনস্টল হতে পারে; তখন সমস্যাটি অ্যাপের আকার বা
   জায়গা নিয়ে। খোলার পর এটি Android সংস্করণ, মডেল, ABI, RAM ও মুক্ত স্টোরেজ দেখায় —
   সেই স্ক্রিনশট পাঠালেই বলে দেওয়া যাবে কোথায় আটকাচ্ছে।
